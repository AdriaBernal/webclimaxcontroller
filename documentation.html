Què és ClimaX Controller?

Sistema de monitoratge agrícola · 2025-2026

ClimaX Controller és una plataforma web dissenyada per a la gestió i monitoratge de sensors climàtics en entorns agrícoles, especialment en vinyes. La seva funció principal és oferir als agricultors una visió en temps real de les condicions ambientals de les seves parcel·les: temperatura, humitat i pressió atmosfèrica, des de qualsevol dispositiu amb navegador web.

El sistema permet registrar sensors geolocalitzats sobre un mapa interactiu, consultar l'històric de lectures de cada sensor i detectar automàticament valors fora del rang òptim per al cultiu. L'accés és per rols: els agricultors gestionen els seus propis sensors, mentre que els administradors gestionen el conjunt d'usuaris de la plataforma.

Arquitectura del sistema

Les tres capes que fan possible el sistema

ClimaX segueix una arquitectura de tres capes, un patró estàndard en el desenvolupament d'aplicacions web modernes. Cada capa té una responsabilitat única i es comunica amb les altres a través d'interfícies ben definides.

NAVEGADOR (Frontend) HTML + CSS + JavaScript │ │ HTTP / JSON (API REST) ▼ SERVIDOR (Backend) FastAPI · Python │ │ Consultes SQL ▼ BASE DE DADES MySQL

Frontend: el que veu l'usuari

La interfície d'usuari és completament estàtica: un conjunt de fitxers HTML, CSS i JavaScript que s'executen directament al navegador sense necessitar instal·lació. Tot el que ocorre visualment (mapa interactiu, gràfiques, taules de lectures, formularis de gestió) és lògica JavaScript que manipula el DOM en temps real.

Backend: el cervell de l'operació

El servidor és una API REST implementada amb FastAPI (Python). La seva funció és actuar de pont segur entre el navegador i la base de dades: rep peticions HTTP del frontend, valida credencials, aplica regles de negoci i retorna dades en format JSON. Cap dada sensible (contrasenyes, lògica d'autenticació) mai toca el navegador directament.

Base de dades: on viuen les dades

MySQL emmagatzema de forma persistent tota la informació del sistema: usuaris, sensors i lectures. L'esquema reflecteix les relacions del domini: un usuari pot tenir molts sensors, i cada sensor acumula moltes lectures al llarg del temps.

Tecnologies utilitzades

Eines i llibreries que formen el projecte

Bootstrap 5

Bootstrap és el framework CSS que dona coherència visual a tota la interfície. Proporciona un sistema de graella de 12 columnes que fa la web adaptable a qualsevol mida de pantalla (responsive design), i un conjunt de components predefinits (botons, formularis, modals, alerts) que acceleren el desenvolupament sense sacrificar qualitat.

Graella responsive Components UI Toasts i Modals

Leaflet.js

Leaflet és la llibreria de mapes interactius de codi obert més estesa del món. Permet renderitzar mapes de teseles (tiles) d'OpenStreetMap i afegir-hi marcadors, popups i events de clic de forma molt lleugera. En ClimaX, cada sensor es representa com un marcador geolocalitzat sobre el mapa, i al fer clic s'accedeix a les seves lectures.

Mapes interactius Geocodificació inversa OpenStreetMap

Chart.js

Chart.js és una llibreria JavaScript per a la visualització de dades mitjançant gràfiques. Permet crear gràfiques de línies, barres o circulars de forma declarativa, simplement proporcionant-li etiquetes i conjunts de dades. En el dashboard, s'utilitza per mostrar l'evolució temporal de temperatura, humitat i pressió de cada sensor seleccionat.

Gràfiques de línies Visualització temporal

FastAPI (Python)

FastAPI és un framework modern per a la construcció d'APIs REST en Python. Destaca per la seva velocitat (comparable a Node.js o Go), la generació automàtica de documentació interactiva (Swagger UI) i la validació automàtica de dades gràcies als tipus de Python. En ClimaX gestiona l'autenticació JWT, les operacions CRUD sobre usuaris i sensors, i la recepció i emmagatzematge de les lectures.

API REST Autenticació JWT Python

MySQL

MySQL és el sistema de gestió de bases de dades relacionals triat per la seva robustesa, àmplia adopció i integració nativa amb Python via connectors com PyMySQL o SQLAlchemy. L'esquema del projecte conté tres taules principals: usuari, sensor i lectura, amb relacions de clau forana que garanteixen la integritat referencial de les dades.

Seguretat i autenticació

Com es protegeix l'accés al sistema

El sistema d'autenticació de ClimaX es basa en tokens JWT (JSON Web Tokens). Quan un usuari inicia sessió correctament, el servidor genera un token signat digitalment que conté el seu identificador i rol. Aquest token es desa al navegador i s'envia automàticament en cada petició posterior al backend, que el verifica sense necessitat de consultar la base de dades en cada crida.

Les contrasenyes mai es guarden en text pla a la base de dades: s'emmagatzemen com a hash criptogràfic. Això significa que ni els administradors del sistema poden recuperar la contrasenya original d'un usuari, únicament restablir-la.

A nivell de frontend, el sistema de rols controla quines seccions del dashboard són visibles per a cada tipus d'usuari: els agricultors veuen el mapa i les seves dades, els administradors accedeixen al panel de gestió d'usuaris.

Flux d'una lectura, de principi a fi

Què passa quan recollim dades d'un sensor

Per entendre com treballen les tres capes juntes, el millor exemple és seguir el camí d'una lectura meteorològica des que l'usuari prem un botó fins que queda desada a la base de dades.

  1. L'usuari prem "Recollir lectures" al popup d'un sensor al mapa. JavaScript captura l'event de clic.
  2. El frontend consulta Open-Meteo, una API meteorològica externa, amb les coordenades GPS del sensor. Rep temperatura, humitat i pressió actuals.
  3. JavaScript actualitza la interfície immediatament: redibuja la gràfica de Chart.js i afegeix una nova fila a la taula de lectures.
  4. El frontend fa un POST al backend (FastAPI) amb les dades de la lectura i el token JWT per autenticar la petició.
  5. FastAPI valida el token, comprova que el sensor pertany a l'usuari autenticat i executa un INSERT a la taula lectura de MySQL.
  6. Les dades queden persistides: la propera vegada que l'usuari o qualsevol altre obri el dashboard, les lectures seguiran hi sent accessibles.
